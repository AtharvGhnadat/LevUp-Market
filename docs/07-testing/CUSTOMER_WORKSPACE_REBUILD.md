## Design, accessibility and implementation review

| Perspective           | Finding                                                                                                                 | Correction and evidence                                                                                                                                                                                                                        |
| --------------------- | ----------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Product design        | Common names were shortened despite spare desktop space. The earlier account menu exposed only settings and sign-out.   | The wide header fits a full ordinary name and groups seven working destinations plus Sign Out. Very long names truncate in the control and wrap in the mobile drawer. The guest and customer controls occupy the same reserved area.           |
| Accessibility         | A very short viewport after rotation briefly retained the previous layout under reduced motion.                         | The reduced-motion rule disables the transitions. Browser checks measure the header immediately after resize. Native modal focus, Escape, restoration, 44px primary controls, labelled fields and invalid-field focus have automated coverage. |
| Frontend architecture | The sign-in and signup layouts shared the same generic side content. A direct order detail also fetched the whole list. | The auth shell gives each workflow a different workbench subject and keeps recovery compact. The order detail issues its own scoped read. Private routing, the header, and the workspace navigation read the same customer route inventory.    |
| Security              | Display metadata and client-provided identity are unsuitable authorization inputs.                                      | Workspace reads use RLS, grant limited editable columns and derive ownership at the database. The provider re-verifies a changed identity. A private email address is never used as the header display-name fallback.                          |
| QA                    | Document width alone missed a chevron extending past the inset header edge at a desktop breakpoint.                     | The search control can yield width, the account area is reserved, and E2E checks the account button against the actual bar as well as the viewport and open menu.                                                                              |
| Asset delivery        | A fresh checkout could serve a Git LFS pointer in place of one of the two authentication photos.                        | The two small, locally served WebPs use regular Git blobs. Browser evidence remains in Git LFS.                                                                                                                                                |

New routes retain the browser’s normal cross-page scroll and history behavior. Same-page anchors move focus and scroll smoothly when motion is enabled. Reduced motion and the Skip to content link jump directly. Standard inputs use native autocomplete and visible field-level feedback.

### Responsive browser evidence

The header and document fit all nine requested viewports, from 320 × 700 through 1920 × 1080. The landscape check used 844 × 390 and the shortened portrait check used 320 × 390. A 390px-wide form with 125% text retained its full width. Native Chromium zoom at 200% produced a 707px effective viewport and a 707px document. At a 1600px viewport the desktop search measured 264 × 44px at the same coordinates before and after login. A physical mobile soft keyboard, Safari/VoiceOver and Android/TalkBack remain unverified.
